Process IO operations

September 11, 2026 阅读约 8 分钟 3933 字
#Computer Organization and Architecture

一、I/O 子系统概述

1.1 什么是 I/O

I/O（输入/输出） 是计算机与外部设备之间交换信息的过程:

  • 输入 ：键盘输入、磁盘读、网络收包
  • 输出 ：显示器输出、磁盘写、网络发包

1.2 I/O 系统层次结构

flowchart TB A["用户程序<br/>printf / fread / socket"] B["用户空间 I/O 软件<br/>C 标准库、系统调用封装"] C["设备无关 I/O 层<br/>文件系统、VFS、协议栈"] D["设备驱动程序<br/>与具体设备交互"] E["中断服务程序<br/>处理设备中断"] F["I/O 硬件<br/>设备控制器、外部设备"] A --> B --> C --> D --> E --> F

1.3 三种 I/O 控制方式

flowchart LR subgraph 查询["程序查询方式"] Q1["CPU 轮询设备状态"] --> Q2["等待就绪"] end subgraph 中断["中断驱动方式"] I1["CPU 做自己的事"] --> I2["设备就绪 → 发中断"] I2 --> I3["CPU 响应中断处理"] end subgraph DMA["DMA 方式"] D1["CPU 设置 DMA 参数"] --> D2["DMA 直接传数据"] D2 --> D3["完成后发中断"] end
方式CPU 干预适用场景
程序查询最多（轮询等待）简单、低速设备
中断驱动中等（中断时处理）中速设备
DMA最少（仅初始化和完成）高速大块数据传输

二、用户空间 I/O 软件

2.1 系统级 I/O vs 标准 I/O

flowchart TD A["应用程序"] --> B["标准 I/O 库<br/>printf / fread / fwrite"] B --> C{"用户缓冲区<br/>是否满/刷新?"} C -->|否| B C -->|是| D["系统调用<br/>read / write"] D --> E["内核"] E --> F["设备驱动 → 硬件"]
类型函数缓冲系统调用次数
系统级 I/Oopen / read / write / close无缓冲每次调用一次
标准 I/Ofopen / fread / fwrite用户态缓冲缓冲满才调用

2.2 文件描述符

在 Unix/Linux 中， 一切皆文件 ：普通文件、目录、设备、管道、Socket、符号链接。

进程启动时默认打开三个文件描述符：

描述符名称流向
0stdin（标准输入）键盘 → 程序
1stdout（标准输出）程序 → 屏幕
2stderr（标准错误）程序 → 屏幕

2.3 标准 I/O 的缓冲类型

缓冲类型触发条件示例
全缓冲缓冲区满才实际 I/O普通文件
行缓冲遇到换行符才实际 I/O终端 stdout
无缓冲每次都实际 I/Ostderr

三、内核空间 I/O 软件

3.1 设备无关 I/O 层

通过 VFS（虚拟文件系统） 提供统一接口：

flowchart TB subgraph VFS["VFS 统一接口"] open["open"] read["read"] write["write"] close["close"] ioctl["ioctl"] end VFS --> A["EXT4 / XFS 文件"] VFS --> B["块设备（磁盘）"] VFS --> C["字符设备（终端）"] VFS --> D["Socket（网络）"] VFS --> E["管道（Pipe）"]

3.2 设备分类与驱动

类型访问方式示例
字符设备按字节流顺序访问键盘、串口、终端
块设备按块随机访问磁盘、SSD
网络设备面向数据包网卡

驱动加载方式 ：

  • 静态编译进内核
  • 动态加载（ .ko 模块）： insmod / modprobe

3.3 中断上半部与下半部

flowchart LR subgraph 上半部["上半部（Top Half）"] A1["关中断"] --> A2["快速应答设备"] A2 --> A3["读取关键数据"] end subgraph 下半部["下半部（Bottom Half）"] B1["开中断"] --> B2["处理协议逻辑"] B2 --> B3["唤醒等待进程"] end 上半部 -->|立即执行| 下半部 下半部 -.->|延迟执行| 下半部
机制特点
软中断（softirq）可并发，性能高
tasklet串行执行，简单
工作队列（workqueue）可睡眠，最灵活

4.3 两种 I/O 编址方式

编址方式说明访问指令代表架构
独立编址I/O 端口独立地址空间in / out 专用指令x86
统一编址（MMIO）端口映射到内存地址空间普通访存指令ARM、MIPS、RISC-V

4.4 中断系统

flowchart LR A["设备发中断"] --> B["CPU 在指令结束时检查"] B --> C["保存现场<br/>PC、PSW 压栈"] C --> D["查中断向量表<br/>找 ISR 入口"] D --> E["执行中断服务程序"] E --> F["恢复现场"] F --> G["iret 返回"]

现代中断控制器 ：

  • APIC ：Local APIC（每核一个）+ I/O APIC（设备中断路由）
  • MSI/MSI-X ：写内存地址触发中断，无需引脚
  • 中断亲和性 ：将中断绑定到指定 CPU 核

五、现代技术扩展

5.1 io_uring：新一代异步 I/O

flowchart LR subgraph 用户态["用户态"] SQ["提交队列 SQ"] CQ["完成队列 CQ"] end subgraph 内核态["内核态"] Engine["io_uring 内核引擎"] end SQ -->|提交请求| Engine Engine -->|完成事件| CQ SQ -.->|mmap 共享| Engine CQ -.->|mmap 共享| Engine
  • Linux 5.1+ 引入，两个共享环形缓冲区
  • 无需系统调用 即可提交 I/O（mmap 共享）
  • 支持文件、网络、定时器等所有 I/O 类型
  • 性能远超 epoll + 线程池

5.2 零拷贝技术

flowchart LR subgraph 传统["传统 read+write"] direction LR D1["磁盘"] --> K1["内核缓冲区"] K1 --> U1["用户缓冲区"] U1 --> S1["Socket 缓冲区"] S1 --> N1["网卡"] end subgraph 零拷贝["sendfile 零拷贝"] direction LR D2["磁盘"] --> K2["内核缓冲区"] K2 --> S2["Socket 缓冲区"] S2 --> N2["网卡 DMA"] end
技术原理
mmap文件映射到用户空间，减少一次拷贝
sendfile内核内直接从文件传到 socket
splice两个 fd 间零拷贝数据移动
DMA网卡直接从内存取数据

5.3 高性能网络 I/O

flowchart TB subgraph 传统["传统网络栈"] A1["网卡"] --> A2["内核协议栈"] A2 --> A3["系统调用"] A3 --> A4["应用"] end subgraph DPDK["DPDK 用户态驱动"] B1["网卡"] --> B2["PMD 轮询<br/>绕过内核"] B2 --> B3["用户态应用"] end
  • DPDK ：绕过内核协议栈，用户态直接驱动网卡，PMD 轮询模式
  • RDMA ：远程直接内存访问，零内核参与，超低延迟
  • XDP ：在网卡驱动层（协议栈前）运行 eBPF 程序，极速包处理

5.4 eBPF：内核可编程

  • 不修改内核代码、不加载内核模块，即可在内核运行沙箱程序
  • 应用：网络过滤、性能分析、安全监控、可观测性
  • 工具：bpftrace、BCC、Cilium

5.5 NVMe 与现代存储

flowchart LR subgraph SATA["SATA SSD"] S1["单队列"] S2["深度 ~32"] end subgraph NVMe["NVMe SSD"] N1["65535 队列"] N2["每队列 65535 命令"] N3["PCIe 通道"] end
  • NVMe ：基于 PCIe，多队列并行，延迟远低于 SATA
  • NVMe-oF ：通过网络（RoCE/TCP）访问远程 NVMe
  • IO 调度器 ：SSD 用 NOOP/NONE，HDD 用 Deadline/CFQ

5.6 设备虚拟化

方案原理性能
全虚拟化QEMU 模拟设备慢
半虚拟化（virtio）Guest 用 virtio 驱动中
直通（Passthrough）物理设备分给 VM接近原生
SR-IOV一个物理设备虚拟多个 VF接近原生

三、综合应用题

  1. 程序要将 1GB 文件通过网络发送：

    • (1) 传统 read+write 需几次数据拷贝？
    • (2) sendfile 可减少几次？
    • (3) 网卡支持 DMA 零拷贝还能如何优化？

  2. CPU 2GHz，每次中断处理 1000 周期，设备每秒 10000 次中断：

    • (1) 中断处理占比？
    • (2) 改 DMA，每 4KB 一次中断，100MB/s 传输，占比？
    • (3) 得出什么结论？

  3. 简述从 printf("hello\n") 到字符显示在屏幕上的完整过程。

参考答案

选择题

  1. A 2. C 3. B 4. B 5. D 6. B 7. C 8. B

简答题要点

  1. 查询：CPU 轮询，利用率低；中断：设备就绪发中断，利用率较高；DMA：控制器直接传输，CPU 干预最少。
  2. 系统 I/O 无缓冲，每次系统调用；标准 I/O 用户态缓冲，减少系统调用次数。
  3. MMIO 将设备寄存器映射到内存地址空间，用访存指令；独立编址用专用 in/out 指令。
  4. 上半部关中断快速处理紧急事，下半部开中断延迟处理非急事，减少关中断时间。
  5. 减少数据在内存中的拷贝。sendfile：内核内文件直接到 socket；mmap：文件映射到用户空间。
