《什么是架构》视频学习笔记

一、核心问题：什么是"架构"？

“架构"这个词在我进入计算机时，就听过很多次——“系统架构"“软件架构"“网络架构”，我其实一直搞不清楚它到底指什么。

“架构”（Architecture）是计算机科学中最模糊的概念之一。 同一个词在不同语境下，可能指代完全不同的东西。这正是我今天要搞明白的第一件事。

二、架构的模糊性

用一个具体的例子来展示这种模糊性——**算术逻辑单元（ALU）**。

ALU 是 CPU 的核心组件之一，负责执行加法、减法、与、或、非等基础运算。但问题来了：

  • 同一个 ALU 功能 ，可以用 完全不同的电路设计 来实现
  • 不同的实现方式，可能使用 不同的操作码（opcode）编码
  • 操作码编码不同 → 软件不兼容

即使功能完全一样，“怎么实现"的差异也可能导致"能不能跑同一个程序"的问题。这就是"架构"一词模糊性的根源——它既可以指"功能规格”（应该做什么），也可以指"具体实现”（怎么做）。

三、ALU 实例：操作码编码与兼容性

进一步展开：假设有两个设计师，各自设计了一个功能相同的ALU，都能做加法、减法、与、或这四件事。但设计师 A 用 `00` 表示加法，设计师 B 用 `01` 表示加法——他们的操作码编码方案不同。

这意味着什么？

  • 如果编译器针对设计师 A 的编码方案生成机器码，这段代码在设计师 B 的 ALU 上 无法正确运行
  • 即使两个 ALU 的"功能"完全一致， 编码方案的差异 也导致了软件层面的不兼容

这个例子让我理解了为什么"架构"不能简单地等同于"功能”—— 编码方案本身也是架构的一部分 。

四、核心辨析：指令集架构（ISA）vs 微架构

这是视频最重要的部分，也是我今天最大的收获。

4.1 指令集架构（ISA）

指令集架构（Instruction Set Architecture） 是 CPU 和软件之间的 契约/接口 。它规定了：

  • CPU 支持哪些指令（如 ADD、SUB、MOV、JMP）
  • 每条指令的操作码编码
  • 寄存器数量和名称
  • 内存寻址方式
  • 异常处理机制

关键特征 ：ISA 是 面向软件的抽象 ，软件（编译器）只关心 ISA，不关心底层怎么实现的。

4.2 微架构（Microarchitecture）

微架构 是 ISA 的 具体硬件实现 。同一个 ISA 可以用不同的微架构来实现：

  • 不同的流水线设计
  • 不同的缓存策略
  • 不同的分支预测算法
  • 不同的执行单元数量

关键特征 ：微架构是 面向硬件的优化 ，同一 ISA 下不同的微架构可以有不同的性能特征。

五、关键结论

通过视频的学习，我总结出三个核心结论：

  1. 同一 ISA 可对应多种微架构 ：例如 x86-64 指令集，Intel 有 Core 系列微架构，AMD 有 Zen 系列微架构，它们都执行相同的 x86-64 指令集，但内部实现完全不同。

  2. 不同 ISA 的软件无法互通 ：为 x86-64 编译的程序不能在 Arm 处理器上直接运行，因为它们的指令集编码不同。这就是为什么手机（Arm）和电脑（x86）不能互相跑对方的 App。

  3. 微架构频繁迭代，ISA 保持稳定 ：现代处理器几乎每年更新微架构（如 Intel 的 Core Ultra、AMD 的 Zen 5），但 ISA 几十年不变（x86 从 1978 年的 8086 沿用至今）。这是因为 ISA 是软件契约，频繁改动会破坏生态兼容性。

六、三层抽象模型

+----------------------------------+
|        应用程序（软件）           |  <- 只关心 ISA
+----------------------------------+
|     指令集架构（ISA）             |  <- 软件与硬件的契约
+----------------------------------+
|     微架构（Microarchitecture）    |  <- ISA 的硬件实现
+----------------------------------+
|        数字逻辑电路               |  <- 晶体管、门电路
+----------------------------------+

这个模型表达了计算机系统的分层思想： 每一层都向上层提供抽象，隐藏下层的复杂性 。

七、与课程知识的关联

课程与"架构"的关联
数字电子技术ALU 的电路实现——这是微架构的底层基础
C语言程序设计写的代码最终会被编译成 ISA 指令——理解代码到硬件的桥梁
**计算机组成原理**（即将学习）直接对应 ISA 和微架构的学习内容
操作系统OS 需要管理硬件资源，理解 ISA 是基础
**编译原理**（未来课程）编译器负责将高级语言翻译成 ISA 指令
计算机网络“网络架构"是另一个维度的架构概念

八、延伸思考

8.1 为什么 x86 能主导 PC 市场？

从架构角度看，x86 的成功不仅仅是因为技术优势，更因为 ISA的兼容性承诺 建立了强大的软件生态。一旦大量软件基于 x86 编译，新的处理器厂商就必须兼容 x86 才能进入市场，形成了路径依赖。

8.2 RISC-V 的兴起

RISC-V 是一个开源的 ISA，它的出现打破了 x86 和 Arm 的格局。作为开源指令集，任何人都可以免费使用和扩展它——这对学术研究和新芯片创业来说是一个巨大的机会。

8.3 Apple Silicon 的启示

Apple 从 Intel x86 切换到自研的 Arm 芯片（M 系列），说明了：

  • 同一 ISA（Arm）下，自研微架构可以带来显著的性能和能效优势
  • 当公司足够大时，可以选择自己的 ISA 路线（Apple 同时维护 Arm ISA 和自研微架构）
